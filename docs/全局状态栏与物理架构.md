# 全局状态栏与物理引擎架构

本文档系统梳理 `GlobalStatusBar` 及其底层状态、物理坐标系的完整映射关系。该系统采用“物理外壳坐标计算”与“内层视觉过渡”彻底分离的双轨架构，并借助独立的状态中枢（Store）实现跨组件通讯及与宿主底层事件的内存同频。

# 内容组成

| 模块名称 | 对应工作区路径 | 说明 |
| :--- | :--- | :--- |
| **全局 UI 入口** | `src/ARK_STATUSBAR/components/GlobalStatusBar.vue` | 常驻浮动状态栏组件，挂载 4 个业务 Tab 并处理物理外壳的样式隔离。 |
| **物理引擎 Hook** | `src/ARK_STATUSBAR/components/global_tabs/useDraggablePhysics.ts` | 拦截拖拽，计算防越界逻辑，根据屏幕半区输出双轨坐标与三态模式。 |
| **共享数据中枢** | `src/ARK_STATUSBAR/components/global_tabs/shared_ui_state.ts` | `GlobalStatusBar` 与所有业务 Tab 的统一防腐层与响应式状态源。 |
| **拦截业务 Tab** | `src/ARK_STATUSBAR/components/global_tabs/interceptor/InterceptorTab.vue` | 渲染即将发送的触发条目，提供状态切换与预览。 |
| **世界书业务 Tab** | `src/ARK_STATUSBAR/components/global_tabs/worldbook/WorldbookTab.vue` | 渲染全量可用世界书的树状手风琴列表及条目挂载管理。 |
| **操作记录 Tab** | `src/ARK_STATUSBAR/components/global_tabs/history/HistoryTab.vue` | 渲染世界书状态修改（Commit）的历史时间线。 |
| **设置面板 Tab** | `src/ARK_STATUSBAR/components/global_tabs/settings/SettingsTab.vue` | 调节窗体尺寸、字体大小及强制重置等系统配置。 |

# 模块一：物理引擎与坐标控制 (`useDraggablePhysics.ts`)

## 状态

| 变量名 | 数据类型 | 初始值/来源 | 精确的业务用途 |
| :--- | :--- | :--- | :--- |
| `UiMode` | `enum` | `FULL`/`MINI`/`BUBBLE` | 状态机枚举。`FULL`: 完整展开; `MINI`: 概览小窗; `BUBBLE`: 气泡态。 |
| `PHYSICS_CONSTANTS` | `object` | 常量集合 | 包含 `SNAP_ALIGN_THRESHOLD` (20, 贴边磁吸), `HIDE_THRESHOLD` (-15, 气泡化阈值), `STRETCH_RELEASE_THRESHOLD` (45, 扯破气泡的展开阈值), `BUBBLE_WIDTH` (32, 默认气泡宽), `MAX_STRETCH` (80, 最大拉伸宽), `EXPAND_BOUNCE_MARGIN` (20, 展开防二次吸附弹开距离), `SAFE_TOP/BOTTOM` (上下防撞墙边距)。 |
| `currentAnchor` | `ref<'left'\|'right'>` | `'right'` | **生死属性**：指示组件当前受哪一侧屏幕边缘管辖。这决定了 CSS `left` 或 `right` 的生效权，彻底防止展开窗体时向反方向野蛮生长。 |
| `transformLeft/Right` | `ref<number>` | `0` / `20` | 组件离左右边缘的绝对物理像素距离。 |
| `transformY` | `ref<number>` | `0` | 组件的 Y 轴坐标，受上下防撞墙常量制约。 |
| `isDraggingState` | `ref<boolean>` | `false` | 提供给外部的拖拽旗标。Vue 据此在物理壳上挂载 `.is-dragging` 以强制禁用 `transition`，保证拖拽零延迟。 |
| `isSnapping` | `ref<boolean>` | `false` | 标识是否处于碰撞或释放后的“自动回弹补间动画”中，Vue 据此挂载 `.is-snapping` 类名重新开启 `transition`。 |
| `isSnappedToEdge` | `ref<false\|'left'\|'right'>` | `false` | 记录组件是否已彻底贴死屏幕边缘，用于判断下一步是“普通位移”还是“橡皮筋拉扯”。 |
| `snappedStretchWidth` | `ref<number>` | `32` | 气泡模式下被拉扯时动态增加的弹性宽度。 |

## 函数

| 函数签名 | 触发时机 | 副作用与逻辑 |
| :--- | :--- | :--- |
| `startDrag(e: MouseEvent \| TouchEvent)` | 鼠标按下/触摸开始 | 记录初始 `startX/Y`，强制关闭 `isSnapping` 动画，向全局挂载位移监听。修改 `isDraggingState = true`。 |
| `onDrag(e: MouseEvent \| TouchEvent)` | 鼠标/触摸移动 | 实时计算差值。若是气泡态，转化为拉伸 `snappedStretchWidth`；若是正常态，修改当前锚点坐标，并在跨越中线时调用 `syncAnchors` 转移控制权。 |
| `stopDrag()` | 鼠标/触摸松开 | 卸载全局监听。若是气泡态，判断拉出距离决定是变为 `MINI` 弹开，还是继续缩回气泡；若是正常态，根据贴边距离判定是否吸附变身。 |
| `checkBounds(forceSmooth=false)` | 定时器/窗口缩放 | 强制将飞出屏幕的组件坐标截断在安全范围 (`SAFE_TOP`, `SAFE_MARGIN_BOTTOM`) 内。 |
| `syncAnchors(viewportWidth, componentWidth)` | 边界检查及中线跨越前 | 互相同步另一侧锚点的绝对数值，保证 `left` 和 `right` 交接瞬间组件不发生瞬移。 |

**核心调用链：**
`startDrag` -> 绑定事件 -> 循环调用 `onDrag` (触发 `syncAnchors` 移交锚点) -> `stopDrag` -> 解绑事件 -> `checkBounds` (最后兜底碰撞处理)。

## 事件

- **向内监听**：
  - 监听原生 `document` / `window.parent.document` 的 `mousemove`, `touchmove`, `mouseup`, `touchend` 以劫持拖拽。
  - `ResizeObserver` 监听 `statusBarEl.value`（外部传进来的容器 Ref），如果非拖拽状态尺寸发生突变，执行 `checkBounds`。
- **向外发射**：无（纯组合式 API 返回 Ref 供外部响应）。

## 样式骨架

决定全局视图生死的核心 DOM 树如下：

```html
<!-- [物理外壳层]：绑定物理引擎输出的 absolute 值。绝不能放宽度/颜色的 transition -->
<div class="ark-global-statusbar-shell" 
     :style="{ left: ..., right: ..., transform: `translateY(${transformY}px)` }">
  
  <!-- [视觉 UI 容器层]：承载业务和 CSS 形变。接收动态 transform-origin -->
  <div class="ark-global-statusbar" 
       :style="{ 'transform-origin': currentAnchor === 'left' ? 'left top' : 'right top' }">
    
    <!-- 气泡态：极度压缩为圆形 -->
    <div v-show="currentUiMode === UiMode.BUBBLE" class="edge-snap-indicator"></div>
    
    <!-- 常规态 -->
    <template v-if="currentUiMode !== UiMode.BUBBLE">
      <div class="statusbar-header">...</div>
      
      <!-- [高跷防线 / Grid 0fr 方案] -->
      <div class="statusbar-content-wrapper" :class="{ 'is-full-expanded': FULL }">
        <div class="statusbar-content-inner">
           <!-- 子面板和内容 -->
        </div>
      </div>
    </template>
  </div>
</div>
```

组件的 UI 完全依赖以下核心类名及嵌套层级，排查样式错乱（如：拖拽栏异常、宽度炸裂、背景色丢失）时，请直接对标此字典：

- **物理外壳层**：`.ark-global-statusbar-shell`
  - **核心样式**：`position: fixed`, `top: 0`, `z-index: 9999`。动态接收 `left`, `right`, `transformY` 绝对值。
  - **动画状态**：`.is-snapping`（用于碰撞回弹的平滑过渡）。
  - **排查点**：如果拖拽坐标错误、突然飞出屏幕，检查外壳的 `style` 绑定。**严禁**在外壳增加宽高相关的 `transition`。

- **视觉 UI 容器层**：`.ark-global-statusbar`
  - **核心样式**：控制圆角、阴影、背景色。最大高度限制为 `max-height: calc(100dvh - 80px)`，自带 `overflow: hidden` 以截断内部滚动溢出。
  - **动态原点**：强制绑定 `transform-origin` 为 `left top` 或 `right top`，这是防伸长撕裂的核心。
  - **状态修饰符**：
    - 主题：`.light-theme`, `.dark-theme`, `.transparent-theme`。
    - 尺寸：`.mini-mode`（强制固定宽度 `180px`），`.edge-snapped`（气泡模式专属）。
  - **排查点**：如果主题变色异常、宽度展开时发生瞬移，检查此类名的 `transition` 及修饰符。

- **拖拽栏 / 头部区域**：`.statusbar-header` (仅 `FULL` 和 `MINI` 模式可见)
  - **核心样式**：`display: flex; justify-content: space-between;`。
  - **交互属性**：强制设置 `cursor: grab`，按住时变为 `cursor: grabbing`。
  - **内部组件**：包含标题 `.title` 和四角折叠按钮 `.icon-btn.toggle-btn`。
  - **排查点**：如果鼠标移到头部无法拖拽、图标错位，检查内部 flex 布局和 DOM 绑定事件（`startDrag`）。

- **气泡吸附把手**：`.edge-snap-indicator` (仅 `BUBBLE` 模式可见)
  - **核心样式**：宽高 100%，居中图标（`justify-content: flex-start / flex-end` 取决于靠哪面墙）。
  - **父级联动变身**：配合父级的 `.edge-snapped-left` 或 `.edge-snapped-right` 类，将靠墙那一侧的圆角（`border-radius`）强行切平为 `0`，营造“从墙里长出来”的视觉。
  - **排查点**：如果气泡无法拖拽或橡皮筋拉扯时图标不跟着走，检查 `justify-content`。

- **内容高度防线（防高跷）**：`.statusbar-content-wrapper`
  - **核心防线样式**：`display: grid; grid-template-rows: 0fr; width: 100%; overflow: hidden;`。
  - **展开状态**：`.is-full-expanded` 修饰符下变为 `grid-template-rows: 1fr;`。
  - **排查点**：如果展开折叠时下方内容瞬间跳变而不是平滑拉开，检查此类名的 `transition: grid-template-rows` 是否丢失。

- **内容撑爆防线（防 Blowout）**：`.statusbar-content-inner`
  - **绝对生命线**：`min-height: 0; min-width: 0; width: 100%;`。
  - **排查点**：如果一串超长报错代码把整个 UI 框架撑得无限宽，且出现了横向滚动条，**百分之百**是因为此类的 `min-width: 0` 被干掉了，导致 Grid 子元素 `min-content` 默认值暴走。

- **红线 CSS 与视觉防线**：
  1. **防止撕裂 (`transform-origin`)**：内层视觉壳必须根据外层物理壳的 `currentAnchor` 动态绑定 `left top` 或 `right top`。确保从 MINI 变为 FULL 变宽时，只能向内（屏幕中心）伸展，否则会发生瞬间位移撕裂。
  2. **防高跷拉伸 (`Grid 0fr`)**：
    ```css
    .statusbar-content-wrapper {
      display: grid;
      grid-template-rows: 0fr; /* 折叠态 */
      transition: grid-template-rows 0.3s;
    }
    .statusbar-content-wrapper.is-full-expanded {
      grid-template-rows: 1fr; /* 展开态 */
    }
    ```
    这是替代 `height` 动画的唯一稳定解。
  3. **防网格爆炸 (`Grid Blowout`)**：
    ```css
    .statusbar-content-wrapper { width: 100%; overflow: hidden; }
    .statusbar-content-inner { min-width: 0; min-height: 0; }
    ```
    在 Grid 布局中，如果不给子项强制设定 `min-width: 0`，一段超长的未折行代码/报错会直接击穿 `1fr` 的限制，撑爆父容器并产生不可控的横向滚动条。

# 拖拽坐标系的动态双轨移交原理

物理外壳如果永远锚定 `right`（右侧），当使用者将其拖拽到屏幕最左侧（例如 `right: 1800px`）并触发面板展开（宽度增加 `200px`）时，由于右侧坐标被锁死，多出来的宽度会强制向左（即屏幕外侧）延伸，导致组件“钻入墙壁”。

为了解决此 Bug，`useDraggablePhysics.ts` 在 `onDrag` 循环中：
1. 实时计算组件的中轴线 `centerX`。
2. 一旦 `centerX` 跨越了屏幕的中线（`viewportWidth / 2`），立刻将 `currentAnchor` 从 `right` 切换为 `left`（或反之）。
3. 切换前，执行 `syncAnchors` 函数，根据当前组件真实的物理宽度，瞬间反推并覆写另一个锚点的值。
结果：用户在拖拽时感觉不到任何异样，但释放并在左边缘展开组件时，由于此时由 `left` 锚定，组件会完美向内（向右）伸展。

# 气泡状态下的橡皮筋反馈流转

在 `BUBBLE` 状态下，窗体极限收缩为一个小圆球（把手）并贴死边缘。此时如果用户按住它向内侧拖动：
1. `onDrag` 不会修改物理坐标（保持贴墙），而是将拖拽位移量 `dx` 转化为正数，并按比例加在 `snappedStretchWidth` 变量上。
2. 组件通过绑定该宽度变量，视觉上产生“被拉长”的橡皮筋黏滞感。
3. `stopDrag` 释放时，如果 `snappedStretchWidth > 45px`，则判定期望展开：瞬间将物理坐标赋予安全弹开距离（`EXPAND_BOUNCE_MARGIN`），并将状态机切换为 `MINI` 态进行视觉展开；否则，宽度直接回退，视觉上“弹回”墙壁。

# 扩展

### 1. 新增一个全局 Tab 面板
如果你想在侧边栏中增加一个新的功能页（如：“资源管理面板”）：
1. 在 `src/ARK_STATUSBAR/components/global_tabs/` 下新建一个目录和 Vue 文件（如 `resources/ResourceTab.vue`）。
2. 打开 `GlobalStatusBar.vue`，在顶部通过 `import ResourceTab from ...` 引入。
3. 找到 `<div class="statusbar-tabs">` 区域，追加按钮并绑定状态：`<button :class="{ active: currentTab === 'resource' }" @click="currentTab = 'resource'">资源</button>`。
4. 找到紧接着的 `<div class="statusbar-content">` 区域，挂载组件：`<ResourceTab v-show="currentTab === 'resource'" />`。

### 2. 添加跨组件的响应式状态
如果新面板和旧面板需要共享一个业务开关（例如：调试模式开关）：
1. 严禁在 Tab 组件内部直接互传 `emit` 或 Props。
2. 直接在 `shared_ui_state.ts` 声明并导出：`export const isDebugMode = ref(false);`。
3. 如果该状态受到环境数据影响，必须在 `shared_ui_state.ts` 的 `setupGlobalListeners()` 中监听对应事件并修改它。所有业务 Vue 页面只需直接导入并渲染该 `ref`。

# 故障排查

| 具体的视觉崩溃/错误症状 | 根本诱因 (Root Cause) | 去哪里检查代码 (Checklist) |
| :--- | :--- | :--- |
| 面板内容过长时，横向出现滚动条，甚至撑破外层悬浮窗的固定宽度。 | Grid 布局下 Flex 子元素的 `min-content` 默认行为导致宽度失控（Grid Blowout）。 | 检查 `GlobalStatusBar.vue` 中的 `.statusbar-content-inner` 类上是否丢失了强制属性：`min-width: 0`。 |
| 拖拽窗体时非常卡顿，感觉鼠标跑出很远窗体才缓慢跟过来。 | 拖拽时物理坐标发生高频变化，却依然被外壳 CSS 的 `transition` 所平滑过渡。 | 检查外壳 `div` 是否成功绑定了由 `isDraggingState` 推送的 `.is-dragging` 类名；并确保 CSS 中存在 `.is-dragging { transition: none !important; }`。 |
| 在 A 面板禁用了某条目，切换到 B 面板发现其依然是开启状态，关闭面板再次打开又恢复了。 | 数据版本分裂（Split Brain）。开发者违规在 Vue 内部用 `ref` 暂存了数据的拷贝，卸载时导致修改丢失。 | 检查相关组件代码，要求所有读取、遍历和修改全部直接基于 `shared_ui_state.ts` 中的 `worldbookEntriesCache`，干掉所有组件内的私有副本。 |
| 展开或折叠窗体时，内容并不是平滑遮罩出现，而是高度瞬间跳跃。 | 把动画加在了不固定的 `max-height` 或是违背了 Grid 收放原理。 | 检查 `.statusbar-content-wrapper` 是否正确保留了 `grid-template-rows: 0fr/1fr` 过渡切换。 |

> **补充要点**
> 1. `GlobalStatusBar.vue` 原有的圆角、模糊背景、边框粗细等 CSS 是对原版的高度重现。所有对 UI 外壳逻辑的修改，绝对不允许侵入并推翻这些 `.ark-global-statusbar` 类的原始审美设计。
> 2. `shared_ui_state.ts` 承载了防腐层（Anti-Corruption Layer）的重大使命。如果宿主的黑盒数据格式在未来发生改变（比如 `WorldbookEntry` 结构改变），**仅允许**在 `shared_ui_state` 中进行数据清洗与字段对齐，决不允许脏数据或原生事件越过这一层污染到 Vue 组件内部。
