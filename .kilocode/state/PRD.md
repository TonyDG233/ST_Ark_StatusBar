# 需求说明文档 (PRD)

## 1. 项目背景与目标
**ST_Ark_StatusBar** 旨在 SillyTavern (酒馆) 环境中构建一个深度还原《明日方舟》体验的“游戏化” RPG 引擎扩展。
本项目从早期失败的纯自动化剧情尝试中衍生而来，致力于通过辅助 UI 和状态管理，改善预设角色卡的游玩体验，降低新用户的上手门槛。

## 2. 核心功能需求

### 2.1 已完成核心功能
目前项目已成功落地并收获好评的两大核心功能：

1.  **开局跳转 UI (Startup Navigator & Return Button)**:
    *   **核心痛点**：用户新建聊天时，不知如何快速切入特定剧情或场景。
    *   **功能实现**：针对新建聊天（或特定楼层），在消息区域直接挂载前端交互界面，允许用户一键选择并应用开局剧本（Scenarios）。同时在非初始刷新的页面提供跳转/返回的按钮入口，方便在不同剧情分支间导航。

2.  **世界书管理器 (Worldbook Manager / GlobalStatusBar)**:
    *   **核心痛点**：由于角色卡包含极其复杂的动态设定，用户手动进入酒馆自带的世界书界面去开关特定条目（如单字干员、各幕剧本）极其繁琐且容易出错。
    *   **功能实现**：提供一个悬浮的、可折叠、跨楼层常驻的独立控制台界面。
        *   **条目总览与快捷干预**：按常驻/条件分类显示条目，支持置顶偏好、快速开关（蓝灯/绿灯切换），一键关闭易触发误判的“单字干员”条目。
        *   **基准线对比与拦截预警 (Baseline Diff & Interceptor)**：将当前世界书状态与作者预设的基准线（Baseline）进行实时对比。如果检测到偏离或配置错误，能在用户点击“发送”时进行前端拦截，避免劣质上下文污染聊天记录。
        *   **操作历史记录 (Git-like Commits)**：对世界书的每一次批量修改（如应用场景、恢复基准线）都会生成一个 Commit，允许用户随时“撤销至此版本”。
        *   **配置防丢持久化**：所有的 UI 设置与历史记录，静默保存在 `[SYS_CONFIG]` 专属世界书条目中。

### 2.2 剧情模块 V2 - 双轨驱动剧情引擎 (当前规划探讨中)
*   **需求痛点**: 社区目前的“自定义思维链 + 手动切换世界书”方案虽然能推进剧情，但严重破坏沉浸感，且预设兼容性极差，容易导致主模型身份超载（既当导演又当演员）。
*   **解决方案 (Shadow Proxy Protocol)**:
    1.  **节点规范化**: 将复杂的幕/节点剧本转换为结构化数据供插件读取，而非一股脑塞给大模型。
    2.  **次级 API 嗅探器**: 拦截用户发送，组装精简的上下文与节点概要，交由次级 API（如小模型）扮演“导演”，判断剧情走向并输出演绎建议。
    3.  **UI 临时审查窗**: 在界面弹出次级 API 的判断结果，供玩家无缝确认或手动微调，再放行。
    4.  **幽灵注入与变量状态同步**: 确认后，将当前剧情节点坐标写入**聊天变量**（防止切存档串线），并将次级 API 的“导演思路”隐秘地注入到用户最新消息的末尾或系统提示中，从而引导主 API 完成精准、高质量的沉浸式扮演。

## 3. 约束与边界
*   必须使用酒馆助手提供的扩展接口（`@types/` 目录），如通过事件总线解耦发送事件。
*   核心插件状态必须只读/写入特定的世界书条目或聊天变量，禁止污染全局设定。
*   主模型单次调用的系统提示词必须被管控，全面向 V2 的“按需节点化注入”架构转型。
