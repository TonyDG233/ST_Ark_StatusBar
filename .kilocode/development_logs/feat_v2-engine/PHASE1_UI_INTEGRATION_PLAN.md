# UI 视觉重构与集成规划 (Phase 1 UI Integration Plan)

本规划文档基于从 Google Stitch 导出的初稿设计代码（`references/参考—UI设计初稿/`），明确了如何将这些设计稿拆解、提炼并缝合到我们现有的 Vue 前端工程中。

## 1. 核心集成策略 (Core Strategy)

我们**绝不会**简单粗暴地将 AI 生成的 HTML 强行替换现有的 Vue 文件。
AI 生成的代码缺乏我们项目深度的上下文（如批量管理、手风琴折叠等复杂交互）。因此，我们的策略是**“提取设计系统 (Design System Extraction)”**：
1. 从导出的 HTML 中提取 Tailwind CSS 配置、色彩变量、按钮切角样式、字体排版。
2. 将你提取出的等高线背景图（`page-bg-dark.jpg` / `page-bg-light.jpg`）作为全局 Asset 引入。
3. 将这些提取出的“皮肤”披在目前我们已有的逻辑骨架（`VUE_TEMPLATES_DUMP.md` 里的数据绑定）之上。

## 2. 架构级调整：双层底栏导航 (Dual-Layer Navigation)

放弃设计稿中单薄的导航方案，根据实际复杂的业务需求，引入**“主底栏 + 次级悬浮底栏”**的结构：

*   **一级主底栏 (Base Nav Bar)**：常驻屏幕底部。
    *   `主页 (Dashboard)`
    *   `多功能 (Misc)` (为后续剧情推演、干员管理预留)
    *   `世界书 (Worldbook)`
    *   `设置 (Settings)`
*   **二级悬浮底栏 (Sub Nav Bar)**：当点击“世界书”时，在主底栏上方弹出一个更扁平、紧凑的二级导航。
    *   `预检拦截 (Interceptor)`
    *   `世界书页面 (Lore Entries)`
    *   `历史记录 (History Logs)`

## 3. 各模块实施方案详述 (Module Specifics)

### A. 全盘采用模块 (Direct Adoption)
对于逻辑相对简单、UI 表现力要求高的模块，我们基本原汁原味地复刻设计稿的排版：
*   **主页 (Main Dashboard)**：直接采用设计稿的布局，作为整个数据枢纽，展示当前剧情节点、理智值、最近触发的世界书条目等。
*   **设置 (Settings)**：直接采用设计稿中的样式，复刻其特有的药丸状分段控制器（Segmented Controls）和滑块样式。
*   **历史记录 (System History)**：直接采用设计稿中的上下结构。顶部使用设计稿中的 3 种操作功能面板（创建快照、全量备份、基准重置），下方使用设计稿中表现极佳的**垂直历史进度条 (Timeline)**。我们将原有的 `CommitHistoryPanel.vue` 数据注入这条时间线中。

### B. 提取样式并自定义重构模块 (Custom Refactoring)
对于交互极度复杂的核心模块，**拒绝照搬设计稿的排版**，只提取其“组件风格”（按钮长什么样、输入框长什么样、面板边框长什么样），然后应用于我们实际的业务逻辑中：
*   **世界书页面 (Lore Entries)**：由于我们需要支持“手风琴折叠”、“批量管理勾选”、“绿/蓝灯状态切换”、“主次关键词输入”等高密度交互，AI 的设计稿完全装不下这些内容。我们将用设计稿的 UI 元素重新粉刷现有的列表结构，确保美观的同时不丢失任何操作效率。
*   **预检拦截 (Interceptor)**：同理，拦截界面需要展示具体的触发原因并要求用户做出“放行/阻断”决策，我们将提取设计稿中的警告色（Hazard Stripes）和巨大按键样式，重塑我们目前的拦截列表。

## 4. 实施步骤与工作量评估 (Roadmap & Workload)

总预计工作量：约 3~4 个工作日（视具体样式调优时间而定）。

*   **第一步：基建与资产挂载 (0.5 天)**
    *   在 `tailwind.config.js` 中注入 Stitch 设计稿里的 `colors` 变量和字体配置 (`Space Grotesk`, `Inter`)。
    *   引入等高线背景图，建立全局 CSS 类（如 `.btn-primary-rhodes`, `.panel-glassmorphism`）。
*   **第二步：外壳与双层导航建设 (0.5 天)**
    *   重构 `GlobalStatusBar.vue`（或新建 `App.vue` 容器），实现刚才规划的一级与二级双层底栏的路由/状态切换逻辑。
*   **第三步：全盘采用模块迁移 (1 天)**
    *   将 Dashboard 和 Settings 页面的 HTML/CSS 搬运过来，绑定 Vue 变量。
    *   重构 History 页面，缝合垂直时间线。
*   **第四步：核心业务 UI 深度定制 (1~1.5 天)**
    *   用新的样式重新手写 Worldbook 列表、搜索框和批量管理工具栏。
    *   用警戒风格重写 Interceptor 弹窗。

## 5. 总结

通过这份规划，我们明确了：**设计稿是素材库，而不是最终的页面。**
我们将吸取设计稿中优秀的排版（如主页、历史线）和科幻质感，但对于真正干活的“世界书”页面，我们将坚持实用主义，在保证操作效率的前提下为其披上这层高级的科幻外衣。

## 附录1：主页与悬浮收纳体系完整方案与评估 (Appendix 1: Dashboard & Bubble System)

基于与核心开发者的深度对齐，针对主页排版、视觉美学定调以及悬浮/贴边状态的痛点，制定以下明确落地方案：

### 1. 导航层级纠偏 (Navigation Hierarchy)
坚决落实主规划中的双层底栏架构，彻底抛弃旧版的扁平 4 Tab，改为：
1. **主页 (Dashboard)**：数据总览、入口分发。
2. **世界书管理器 (Worldbook Manager)**：点击后展开二级菜单（包含：**拦截预警**、**条目管理**、**历史记录**）。
3. **多功能 (Misc - 占位)**：为未来的剧情推演节点、附属功能预留的扩展区。
4. **系统配置 (Settings)**。

### 2. 主页排版与“画饼”组件 (Dashboard Layout & WIP Mask)
*   **非对称操作区**：采用设计稿中 `grid` 布局的“一大两小”模块划分（如左侧占据主位的大区块，右侧叠放两个小区块），以视觉面积直观表达业务重要级，也为后续低成本追加新入口提供高度可扩展性。
*   **WIP 预告遮罩组件 (`<ArkWipMask>`)**：开发一个高复用性的独立遮罩组件。当主页或导航中出现尚未实装的功能（如“剧情模式”）时，对该区块施加变灰/去色滤镜，并在其上覆盖具有方舟风格（斜条纹/高对比纯色块）的“敬请期待 (STAY TUNED)”遮罩。满足画饼预告需求，同时保持 UI 整体美观。

### 3. 美学纠偏与悬浮/收纳体系交互演进 (Bubble & Mini Mode UX)
**美学共识**：不再沉迷于老套的“蓝紫发光描边”科幻，转向前沿游戏UI的“高级极简主义与纯色区块拼接”。

**痛点与交互优化设计**：
当前最大的体验痛点是自动化收缩的缺失：触发拦截时 UI 会展开，但点击“发送/阻断”处理完毕后，UI 却不会自己缩回去，严重打断了玩家阅读正文的沉浸感。

*   **状态 A：极限贴边气泡 (Bubble Mode)**
    *   **核心准则**：保持极其克制的小体积，绝对不向气泡塞入文本导致其体积膨胀，失去作为“不遮挡正文的收纳态”的意义。
    *   **引出式微型看板 (微交互创新)**：当处于气泡模式且触发拦截时，**不再强行弹开整个庞大的 UI 面板**。而是采用类似“战术地图局部放大”或“漫画引出对话框”的风格，从气泡旁无缝延展出一个极小的悬浮浮层。该浮层仅展示缩略版的拦截列表及“放行/阻断”按钮。**操作处理完毕后，浮层立即消失，自动恢复为安静的贴边气泡状态。**
    *   **手势冲突规避 (双击展开)**：鉴于全面屏手机的“侧边滑动返回”手势极易与气泡的“向内拖拽拉出”物理引擎冲突。将为气泡窗显式**添加双击 (Double Tap) 交互**，双击后 UI 将自动弹射展开为悬浮小窗模式，提供更稳定可靠的触发途径。
*   **状态 B：悬浮小窗 (Mini Mode)**
    *   **视觉骨架对齐**：解决当前“无拦截时头部极扁，有拦截时突然被撑得又细又长”的割裂感。将重构一个具有稳定基础高度和比例的骨架容器，不论内部是否有列表数据，视觉外轮廓都保持统一感（原有的丝滑拉伸物理逻辑予以保留）。
    *   **双态切换**：在悬浮小窗的头部增加极其轻量的切换控件，允许玩家在“显示当前剧情节点信息（未来实装）”与“显示拦截列表”之间平滑切换。

### 4. 自由缩放功能 (Global Resizing)
赋予面板外框原生的**拖拽拉伸能力 (Resizable)**。通过在 UI 边角注入缩放把手，允许用户直接在主界面快速调整 UI 的长宽大小，免去前往 Configuration 菜单调整拉条的繁琐步骤，提升操作连贯性。
