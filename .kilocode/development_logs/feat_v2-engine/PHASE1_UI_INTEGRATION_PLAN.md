# UI 视觉重构与集成规划 (Phase 1 UI Integration Plan)

本规划文档基于从 Google Stitch 导出的初稿设计代码（`references/参考—UI设计初稿/`），明确了如何将这些设计稿拆解、提炼并缝合到我们现有的 Vue 前端工程中。

## 1. 核心集成策略 (Core Strategy)

我们**绝不会**简单粗暴地将 AI 生成的 HTML 强行替换现有的 Vue 文件。
AI 生成的代码缺乏我们项目深度的上下文（如批量管理、手风琴折叠等复杂交互）。因此，我们的策略是**“提取设计系统 (Design System Extraction)”**：
1. 从导出的 HTML 中提取 Tailwind CSS 配置、色彩变量、按钮切角样式、字体排版。
2. 将你提取出的等高线背景图（`page-bg-dark.jpg` / `page-bg-light.jpg`）作为全局 Asset 引入。
3. 将这些提取出的“皮肤”披在目前我们已有的逻辑骨架（`VUE_TEMPLATES_DUMP.md` 里的数据绑定）之上。

## 2. 架构级调整：双层底栏导航 (Dual-Layer Navigation)

放弃设计稿中单薄的导航方案，根据实际复杂的业务需求，引入**“主底栏 + 次级悬浮底栏”**的结构：

*   **一级主底栏 (Base Nav Bar)**：常驻屏幕底部。
    *   `主页 (Dashboard)`
    *   `多功能 (Misc)` (为后续剧情推演、干员管理预留)
    *   `世界书 (Worldbook)`
    *   `设置 (Settings)`
*   **二级悬浮底栏 (Sub Nav Bar)**：当点击“世界书”时，在主底栏上方弹出一个更扁平、紧凑的二级导航。
    *   `预检拦截 (Interceptor)`
    *   `世界书页面 (Lore Entries)`
    *   `历史记录 (History Logs)`

## 3. 各模块实施方案详述 (Module Specifics)

### A. 全盘采用模块 (Direct Adoption)
对于逻辑相对简单、UI 表现力要求高的模块，我们基本原汁原味地复刻设计稿的排版：
*   **主页 (Main Dashboard)**：直接采用设计稿的布局，作为整个数据枢纽，展示当前剧情节点、理智值、最近触发的世界书条目等。
*   **设置 (Settings)**：直接采用设计稿中的样式，复刻其特有的药丸状分段控制器（Segmented Controls）和滑块样式。
*   **历史记录 (System History)**：直接采用设计稿中的上下结构。顶部使用设计稿中的 3 种操作功能面板（创建快照、全量备份、基准重置），下方使用设计稿中表现极佳的**垂直历史进度条 (Timeline)**。我们将原有的 `CommitHistoryPanel.vue` 数据注入这条时间线中。

### B. 提取样式并自定义重构模块 (Custom Refactoring)
对于交互极度复杂的核心模块，**拒绝照搬设计稿的排版**，只提取其“组件风格”（按钮长什么样、输入框长什么样、面板边框长什么样），然后应用于我们实际的业务逻辑中：
*   **世界书页面 (Lore Entries)**：由于我们需要支持“手风琴折叠”、“批量管理勾选”、“绿/蓝灯状态切换”、“主次关键词输入”等高密度交互，AI 的设计稿完全装不下这些内容。我们将用设计稿的 UI 元素重新粉刷现有的列表结构，确保美观的同时不丢失任何操作效率。
*   **预检拦截 (Interceptor)**：同理，拦截界面需要展示具体的触发原因并要求用户做出“放行/阻断”决策，我们将提取设计稿中的警告色（Hazard Stripes）和巨大按键样式，重塑我们目前的拦截列表。

## 4. 实施步骤与工作量评估 (Roadmap & Workload)

总预计工作量：约 3~4 个工作日（视具体样式调优时间而定）。

*   **第一步：基建与资产挂载 (0.5 天)**
    *   在 `tailwind.config.js` 中注入 Stitch 设计稿里的 `colors` 变量和字体配置 (`Space Grotesk`, `Inter`)。
    *   引入等高线背景图，建立全局 CSS 类（如 `.btn-primary-rhodes`, `.panel-glassmorphism`）。
*   **第二步：外壳与双层导航建设 (0.5 天)**
    *   重构 `GlobalStatusBar.vue`（或新建 `App.vue` 容器），实现刚才规划的一级与二级双层底栏的路由/状态切换逻辑。
*   **第三步：全盘采用模块迁移 (1 天)**
    *   将 Dashboard 和 Settings 页面的 HTML/CSS 搬运过来，绑定 Vue 变量。
    *   重构 History 页面，缝合垂直时间线。
*   **第四步：核心业务 UI 深度定制 (1~1.5 天)**
    *   用新的样式重新手写 Worldbook 列表、搜索框和批量管理工具栏。
    *   用警戒风格重写 Interceptor 弹窗。

## 5. 总结

通过这份规划，我们明确了：**设计稿是素材库，而不是最终的页面。**
我们将吸取设计稿中优秀的排版（如主页、历史线）和科幻质感，但对于真正干活的“世界书”页面，我们将坚持实用主义，在保证操作效率的前提下为其披上这层高级的科幻外衣。

## 附录1：主页与全局交互体系终极规范 (Appendix 1: Ultimate UI & Interaction Specs)

基于对实际使用痛点与审美疲劳的深度反思，确立以下 14 条必须绝对遵守的开发红线：

### 一、全局交互与架构层 (Global Interaction & Architecture)
1. **分页隔离防重叠**：底层路由（如主页、设置页的切换）必须使用 `v-if` 或严格的碎片节点包裹防范，绝对杜绝组件因生命周期问题导致的上下堆叠、穿模。开局 UI 与全局状态栏的挂载生命周期必须严格互斥。
2. **边缘防手势冲突 (双击展开)**：全面屏手机“侧滑返回”手势易与“贴边气泡拉出”动作冲突。必须为贴边气泡添加**双击 (Double Tap)** 行为，双击直接弹出悬浮窗。
3. **全局自由缩放 (Resizable UI)**：给全局 UI 外框的边角添加可拖拽拉伸的把手，使用户无需进入设置菜单即可直观调整界面长宽比例。
4. **极端宽度自适应 (200px - 1000px)**：摒弃死板的 `md:` 屏幕宽度媒体查询。引入容器查询 (Container Queries) 或 Flex-wrap。当用户将 UI 压缩至极端的 200px 时，原有的左右并排按钮必须自动重排为上下结构，严禁文字挤爆或截断。

### 二、贴边气泡态 (Bubble Mode) 的战术化重制
1. **身份图标回归**：废除一切无关图标（如 Terminal），必须使用“书本”图标（对应世界书管理器核心身份）。
2. **文案极致压缩**：气泡上绝不允许出现“预警拦截”等冗长废话。采用极简模式：`[书本图标] 拦截: X`。
3. **引出式战术弹窗 (核心交互重制)**：
   * 触发拦截预警时，**严禁暴烈展开整个全屏/半屏 UI 界面遮挡小说正文**。
   * 维持贴边气泡形态，仅在气泡旁像“战术放大镜/漫画气泡”一样引出一个悬浮小菜单。
   * 该小菜单仅展示最精简的拦截列表与放行/阻断按钮。处理完毕后悬浮框自动消失，恢复安静的极简贴边气泡。

### 三、悬浮窗态 (Mini Mode) 的骨架与信息流
1. **视觉骨架统一化**：坚决消灭“空内容时极扁、出现内容时瞬间拉长”的视觉割裂感。悬浮窗必须拥有一个稳定的基础视觉外延和高度比例，内部留白，维持视觉重心的稳定（底层丝滑拉伸物理逻辑予以保留）。
2. **双态视图切换**：在悬浮窗模式下，顶部必须提供轻量化切换开关，允许玩家在“显示当前剧情节点信息（未来功能）”与“显示拦截列表（当前功能）”之间来回切换。

### 四、主页 (Dashboard) 的排版与美学定调
1. **非对称层级排版**：底部导航或快捷操作区延续“一大两小”等非对称网格（Grid）布局。通过视觉面积直观定义业务主次（如世界书管理是大按钮，附属功能是小按钮），杜绝平庸的铺大饼。
2. **纯净全中文适配**：我们不是英语用户。坚决剔除诸如 `剧情推进进度 (PLOT_PROGRESS)` 这种自作聪明、拉低信息密度、破坏狭窄排版的中英混排形式。全盘使用纯中文极致精简标签。
3. **精准画饼遮罩 (WIP Mask)**：遮罩组件的用法必须精准——**仅针对已经绘制出的实体组件，由于后端功能暂未接入，在其之上覆盖带有“敬请期待”的灰色半透明滤镜遮罩**。绝对不是新建一个毫无组件的空白页面糊上遮罩。
4. **真实拦截记录日志**：主页中部的区块不是用来展示假数据的“终端日志”，而是**拦截记录**。直接绑定并回显上一轮触发的世界书条目内容。
5. **极简色块美学**：方舟味绝非死板的直角和发光描边。前沿战术风格已向大杂烩演进，核心在于**极简主义的纯色区块拼接**。杜绝廉价科幻的蓝紫高亮框，色彩对比度必须优先服务于文本的绝对可读性。

## 附录2：Feature-Sliced Design 目录树规划 (Appendix 2: FSD File Structure)

为彻底解决业务组件与基础 UI 积木混杂的困局，建立基于功能切片（Feature-Sliced Design, FSD）的目录规范。以下为改造后的目标结构树：

```text
src/ARK_STATUSBAR/
├── styles/                         # 【全局基建】存放 tailwind_themes.scss 等纯粹的 CSS 变量
├── components/                     # 【基础 UI 积木】存放跨模块通用的无脑视觉组件
│   ├── ArkButton.vue               # 方舟风格折角按钮
│   ├── ArkPanel.vue                # 带呼吸角缀的背景面板
│   └── ArkWipMask.vue              # "敬请期待"开发中遮罩层
│
└── views/                          # 【业务视图层】承载页面与专属逻辑
    ├── GlobalStatusBar.vue         # 物理拖拽外壳，顶级路由与缩放引擎
    └── global_tabs/
        
        ├── dashboard/              # 【模块 1：主页总览】
        │   ├── DashboardTab.vue    # 主面板 MVP：组合一大两小操作区
        │   └── components/         # 仅主页独享的特定卡片组件
        │
        ├── worldbook_manager/      # 【模块 2：世界书管理器】（下辖原三大核心）
        │   ├── WorldbookManagerTab.vue  # 二级导航条容器
        │   ├── interceptor/        # （降级为子模块）
        │   │   ├── InterceptorPanel.vue # 拦截预警业务
        │   │   └── hooks/          # 拦截器专属 Hook
        │   ├── lore_entries/       # （降级为子模块，原 worldbook）
        │   │   ├── LoreEntriesPanel.vue 
        │   │   ├── WorldbookEntryList.vue
        │   │   └── useWorldbookActions.ts # 条目管理专属 Hook
        │   └── history/            # （降级为子模块）
        │       ├── SystemHistoryPanel.vue 
        │       └── CommitHistoryCard.vue
        │
        ├── misc/                   # 【模块 3：多功能预留区】
        │   └── MiscTab.vue         # 预埋位，挂载 <ArkWipMask>
        │
        └── settings/               # 【模块 4：系统配置】
            └── SettingsTab.vue     # 主题、透明度、全局滑块控制
```
