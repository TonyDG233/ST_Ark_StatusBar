# ARK_GAME (Story Engine V2) 开发总规划

## 1. 核心愿景
彻底摆脱 V1 阶段“通用世界书管理器”的包袱，利用 V1 沉淀的世界书管理技术（开关、快照、历史记录），从头开始在 `src/ARK_GAME` 目录下构建一个**纯粹、沉浸式、逻辑自洽的明日方舟角色卡游戏引擎**。

## 2. 核心架构原则
- **物理隔离**：V2 在 `src/ARK_GAME` 下独立开发，拥有自己的 `index.ts`，Webpack 将其自动独立打包为 `dist/ark_game/index.js`。
- **命名空间隔离**：V2 的存储键值（如 `ark_game_settings`）与事件总线（`arkv2:xxx`）必须与 V1 完全隔离，确保在同仓库开发或同时安装时绝不冲突。
- **按需继承**：不全盘复制 V1 代码。只将 V1 中经过验证的纯净底层（如 `worldbook_mapper.ts`, `entry_service.ts`, `logger.ts`）剥离 UI 后“移植”到 V2。
- **双轨剧情流水线**：落实 `01_architecture_discussion.md` 中的设计，将重度剧情判断交给“次级API + 人工确认窗”，将纯净剧本投喂给“主API”。

## 3. 开发阶段规划 (Milestones)

### 第一阶段：温和重构与模块化开关 (Incremental Refactoring & Toggles)
- [ ] **组件独立挂载与开关机制**：重构 `src/ARK_STATUSBAR/index.ts`。为除去后台逻辑之外的所有前端组件（如全局世界书管理器、开局UI、返回按钮）分别设置独立的挂载判断与全局开关。
- [ ] **预设模式切换**：实现两套默认的“开关预设方案”——一套作为“通用世界书插件”（默认开启全局管理器，关闭方舟UI），一套作为“方舟角色卡专属”（根据 `isArknights` 动态开启开局UI和特有功能）。这为将来项目规模变大后，通过简单的代码复制+删减非必要组件即可打包出独立插件铺平了道路。
- [ ] **配置存储解耦 (Config Storage Split)**：重构 `system_config.ts` 和 `config_store.ts`。将世界书修改记录（Commits/History）等跨业务的核心共享数据单独剥离出来，存入一个独立的、共用的持久化键值（例如 `ark_shared_history`）中。这样其他组件或未来独立出来的管理器在读取/写入历史记录时，就不需要去处理对方的 UI 偏好配置，彻底杜绝脏写。

### 第二阶段：人类驱动原型，AI 实现 UI (Prototyping & Extension)
- [ ] **人机协作流确立**：关于后续更复杂的剧情UI（类似手机OS、剧情分支选项等），采取 **“人类提供视觉原型/排版草图 -> AI 负责代码实现与动画”** 的开发模式。
- [ ] **UI 迭代**：基于人类提供的参考，用现代前端技术重构开场界面和游戏内临时交互窗（如弹出的次级判断确认窗）。
- [ ] **核心架构延伸准备**：在现有（经过删减重构的）基础之上，规划新业务的接入点。例如，思考未来的“双轨拦截器”如何在不破坏现有 Vue 生命周期的情况下，桥接到已有的消息系统中。

### 第三阶段：双轨剧情引擎 (Dual-Track Interceptor Pipeline)
- [ ] **数据规范化**：设计严格的 `ArkStoryNode` 剧本节点数据结构（包含 NodeID, 简介摘要, 完整剧本, 关联节点）。
- [ ] **发送拦截与次级调用**：重构拦截器，截断发送动作，组装 `[剧情节点树摘要 + 对话记录]`，发起次级小模型（如 Flash）判定调用。
- [ ] **导演审查窗 (Edit Window)**：开发临时弹出 UI，向玩家展示次级 API 给出的“剧情方向与导演建议”，允许玩家编辑或放行。
- [ ] **幽灵注入 (Ghost Injector)**：放行后，根据选定的 NodeID 自动调度 `entry_service` 激活完整剧本条目，并将导演建议无痕注入主模型请求末尾。

### 第四阶段：状态持久化与外部生态 (State & Sync)
- [ ] 利用酒馆提供的聊天级变量 (Chat Variables)，将当前剧本坐标（NodeID）等进度数据落盘，实现多存档相互独立。
- [ ] 探索与酒馆社区“数据库插件”的联动机制，实现长线记忆防偏移。

## 4. 下一步行动纲领
当前首要任务是完成**第一阶段**的物理建城：建立 `src/ARK_GAME` 目录，编写最简入口并确认 Webpack 正确将其打包；然后将纯净的世界书 API 搬运并跑通，为后续的 UI 和剧情管线打下地基。
