> **文档定位**：这是启动「按 `3_2_shujuku逆向取舍边界与剧情模块完整性定稿.md` 逐步逆向迁移 shujuku 数据库内容」的**执行交接书**。本任务聚焦**阶段一：底座**（记忆召回 + 记忆存储 + 变量引擎），是后续剧情加法（plot_nodes / 幕开关 / C9b）的**地基**。

## 一、 任务目标（与 3_2 对齐）

让用户从 shujuku 插件转到本项目私有化数据库引擎后，**用户体验不丢失**。依据 `3_2` 的迁移底线三判据：

- **① 数据契约（必迁）**：SQLite 底座、8 张核心表、表格模板预设、填表规则、剧情推进预设 + API 预设库、各类提示词导入导出、旧档 V1↔V2 无损兼容。
- **② 行为契约（必迁）**：自动填表调度（频度阶梯 + skipFloors + 手动 N 层）、填表执行 + 自愈、召回（天之音）、总结（美杜莎）、WAL/Checkpoint/撤回重播 + stable-row_id、跨聊天 Checkpoint 导出/导入、可视化表格编辑/手动改数据。
- **③ 可替代判据（降级迁移）**：语义向量→大纲检索；Agent 拓扑→简单节点开关；绿灯接管→幕级开关；Schema 调和→迁移脚本；严格 JSON 协议→可选分支。

**本任务只做①和②（底座）**，以及③中与底座相关的降级；**剧情加法（`3_2` §四）不属于本任务**。

## 四、 底座逆向迁移范围（3_2 A 区保留项 + 数据/行为契约）

### 4.1 记忆存储（Storage）—— 不可丢
| 机制 | 物理对应 | 说明 |
|---|---|---|
| **纪要表 `chronicle`** | SQLite 表（time_span / location / chronicle_entry / summary / code_index） | 长期记忆物理载体，AM 编码存放处 |
| **AM 编码体系** | `AM0001`… 连续递增不跳号 | 时间线记忆索引坐标、召回基础单位 |
| **WAL / Checkpoint / sql_delta** | ChatMetadata 快照 + 楼层增量 | 持久化与撤回一致性，状态不腐化 |
| **stable-row_id 锁** | `stable-row-id-allocator` | 删行/合并后主键不重用，防记忆定位错乱 |
| **V1↔V2 无损兼容** | SyncBridge | 老档原地读取、不改数据类型、不丢档（**含 3_2 §六.1 的 TEXT 类型修正**） |

### 4.2 记忆召回（Recall）—— 不可丢、原样兼容
| 机制 | 物理对应 | 说明 |
|---|---|---|
| **天之音 前置召回（C9a）** | Pre-Main Call，从 chronicle 匹配相关 AM 编码 | **数据库最核心功能，原样兼容，绝不替换** |
| **时间词映射** | now/today/days/weeks/months/years/old | 把编码译为自然时间词，注入体验关键 |
| **幽灵注入** | 替换入 `{{story_hook}}` 类占位 | 让主模型正文自带前后因果 |
| **美杜莎 总结（C11）** | CoAT 7 步合并未精简纪要 | 抗熵 + 生成规范 AM 行，是"总结"的物理实现 |

### 4.3 变量引擎与查询（底座支撑）
- **C1 SqliteEngine**（asm.js 无头，已有 `core/db/SqliteEngine.ts`）。
- **C8 stable-row_id 锁**、**C15 Chat Scope 隔离**（切卡/切聊清洗）、**C19 跨聊天快照迁移**。
- **C6 NameMapper + C7 ORM**（`db.表.where()` 链式查询，可降级）。
- **C10 填表人 + UpdateOrchestrator 自愈**、**C16 自动填表调度**、**C20 严格 JSON 填表协议分支**。
- **基础杂项**：API 设置、表格模板/全局预设、填表规则、剧情推进预设 + API 预设库、各类提示词导入导出。

## 五、 分步执行顺序（逐步，每步可验收）

1. **复核比对**：对照逆向事实文档（1_0~1_3）与真实源码，产出「已逆向 / 未逆向 / 未移植」清单，标出本任务要补的缺口。
2. **数据契约修正**（先保旧档无损）：修正 `SyncBridge` 单元格类型（见 `3_2` §六.1：SchemaMapper 按数据推断列类型；导出保留单元格原始类型，不做 `String()` 强转）。
3. **记忆存储闭环**：chronicle + AM 编码 + WAL/Checkpoint/sql_delta + stable-row_id 锁 + 撤回/Swipe 5ms 重播。
4. **记忆召回闭环**：天之音 C9a（AM 召回 + 时间词映射 + 幽灵注入）。
5. **总结闭环**：美杜莎 C11 CoAT 7 步合并（依 `DEFAULT_MERGE_SUMMARY_PROMPT_SQL_ACU` 反推）。
6. **变量引擎与查询**：C10 填表 + UpdateOrchestrator 自愈 + C16 调度 + C20 协议 + C6/C7 ORM + C15 Scope + C19 迁移。
7. **数据契约杂项**：导入导出、预设、填表规则、提示词导入导出。
8. **测试与收口**：扩展 `core/__tests__/db.test.ts`，每步断言通过，无飘红。

## 六、 验收判据（对应底座，缺一环即视作"记忆核心丢失"）

- 老档 `chronicle` 无损读取，AM 编码连续、时间词映射正确。
- 撤回 / Swipe 后记忆状态 **5ms** 恢复，不与剧情坐标错乱。
- 美杜莎能将未精简纪要压缩为规范 AM 行并擦除旧明细。
- `SyncBridge` 往返后**单元格类型与旧档完全一致**（数字仍为数字、`null` 仍为 `null`、载体仍为 V1 JSON）。
- 填表人 SQL 执行 + 报错自愈重试闭环跑通。
- 上述任一环节缺失，必须回退补齐，不得以"简化/剧情优先"为由跳过。

## 七、 红线（不可违背）

- **记忆召回（天之音 C9a）与记忆存储（chronicle/AM/WAL/stable-row_id/美杜莎）是 shujuku 最核心、用户唯一点名"必需"的底座，绝对禁止视为可裁剪项或可被剧情替换**。剧情节点定位（C9b）只是叠加其上的加法，**不是替换**。
- **读什么存什么**：读取哪些数据就存哪种数据（保持原格式与类型），确保切回 shujuku 插件无副作用。
- 本任务在 `src/sandbox_shujuku/` 沙盒内完成，**严禁改动主项目**。
- 不臆造 shujuku 不存在能力；以 `@types` 与真实源码为准；严禁鸭子类型 / `any` 绕过编译器。
- 与剧情侧「节点逻辑转写」（`TASK_HANDOFF_剧情世界书解析器与DAG标准.md`）**独立、可并行**，互不阻塞。
