## 二、 导出世界书的顶层物理 JS/JSON 数据结构 (Worldbook JS Structure)

经多样本物理分析证实，社区导出的剧情世界书 `.json` 文件顶层**不含** `name` 或 `description` 等元数据属性，整个 JSON 文件的根节点仅包含唯一的 `"entries"` 键，承载所有的世界书条目：

```json
{
  "entries": {
    "0": {
      "uid": 0,
      "key": [],
      "keysecondary": [],
      "comment": "Stormwatch第一幕",
      "content": "注意：该幕为“风暴瞭望sw1”\n...",
      "constant": true,
      "selective": false,
      "enabled": true,
      "position": 0,
      "exclude_from_search": false
    }
  }
}
```

其对应在前端及无头核心中的 TypeScript 契约定义如下：

```typescript
interface SillyTavernExportedWorldbook {
  entries: {
    [key: string]: {
      uid: number;
      key: string[];                 // 主激活关键词数组（幕级条目为空）
      keysecondary: string[];        // 辅助激活关键词数组
      comment: string;               // 开发者注释（如 "Shatterpoint第一幕"、"喀利喀"）
      content: string;               // 条目的核心文本内容
      constant: boolean;             // 是否为常驻激活条目
      enabled: boolean;              // 是否默认启用
      position: number;              // 消息历史流中的物理注入位置
      [key: string]: any;            // 其他酒馆原生渲染控制参数
    }
  };
}
```

## 三、 世界书条目的四大功能分类与排版特征 (The 4 Functional Categories)

在物理 `.json` 文件中，所有 `entries` 内的对象在功能上被高度特化为以下四种独立的条目类型：

### 1. 逻辑条目 (Logic & Outline Entries)
* **存在形态**：有两种物理存在形态，取决于剧本作者的排版习惯。
  * **形态 A (独立逻辑条目)**：在怀黍离、画中人、登临意、相见欢、辞岁行、雅赛努斯、启程、阴云火花、太阳甩在身后等绝大多数世界书中，存在一个 `comment` 包含 `"剧情节点发生逻辑"`、`"剧情节点梳理"` 的**独立条目**，常驻开启。
  * **形态 B (嵌套型逻辑)**：在《风雪过境.json》等世界书中，逻辑头直接作为第二段**物理嵌套在剧本幕级条目的开头部分**。
* **文本结构**：以 `第一幕\n剧情节点...` 或以 `幕简介：` 形式平铺说明该幕下各细分节点之间的前后时序、先后继承或平行发生关系（属于静态大纲，无需大模型热重写）。

### 2. 剧本幕级条目 (Act Script Entries)
* **存在形态**：以 `"第一幕"`, `"Shatterpoint第一幕"`, `"后日谈"` 等命名的独立条目。
* **控制特征**：触发键 `key` 与 `keysecondary` 保持为空数组 `[]`（防止因日常对话词汇误触激活）；`constant` 恒为 `true`。
* **文本结构**：
  * **元数据定位头**：第一行通常固定为 `注意：该幕为“...”` 或 `注意，这一幕为"..."`。
  * **具体节点正文**：平铺多个具体的剧情节点段落。每个子节点均以一个标准的“节点标题行”作为起点，后续跟随该节点的内容详情（如 `主要内容：`、`本节点重要对话参考：`）以及行格式 `[角色名称]：[台词]` 的全量对话剧本。

### 3. 导航与总览条目 (Navigation & Summary Entries)
* **存在形态**：以 `[玩家导航]...` 命名的辅助条目，多存在于大型多线剧本中（如《慈悲灯塔》中的阿米娅/博士/凯尔希线、典范军线、W/佣兵小队线轨迹说明）。
* **文本结构**：对本章节所包含的所有幕进行整体的轨迹归纳和阶段划分，指示玩家该如何手动切换幕条目。

### 4. 补充设定与干员/角色档案 (Character profiles & Environment Settings)
* **存在形态**：单独的触发条目（如干员代号 `"喀利喀"`、`"Whitesmith"`、`"哈洛德"`，或环境效果 `"[推王插剑前开我关02]维多利亚战场环境01"`）。
* **控制特征**：`constant` 通常为 `false`；其 `key` 数组中配置了具体用于词义匹配触发的关键词（如 `["尚冢","挑山人"]`、`["山雪鬼"]`）。
* **文本结构**：采用 `基本信息`、`外表`、`外貌：` 等固定段落结构，平铺说明人设背景、外貌、武器装备及源石病感染情况。

## 四、 节点内文本划分与排版特征 (Internal Node Layouts)

在大文本内，各个子剧情节点没有被拆分为独立的 entries，而是平铺在大文本内。其内部文本划分存在以下四个物理排版规约：

1. **主要内容/概括 (Summary)**：
   * 紧接在标题行下方，常以 `主要内容：`、`描述：` 或直接段落文本的形式平铺，用于说明本节点发生的事件概述。
2. **环境描写 (Environment)**：
   * 在部分剧本（如《慈悲灯塔》）中，使用花括号进行物理隔离：`如下用{}包括的是周围的环境\n{\n[环境描写文本]\n}`。
3. **选项分支 (Options)**：
   * 在部分节点（如《主线第一至第五章.json》）中，提供了显式的分支选择提示，格式为：`选项：\n- "博士": [选项文本]`。
4. **对话/剧本台词段 (Script Dialogues)**：
   * 始终以 `本节点重要对话参考：`、`节点重要对话参考：` 或 `本剧情节点重要对话参考：` 标头引出。
   * **台词双重排版特征（关键事实）**：
     * **双引号包裹型 (Quoted Name)**：格式为 `"[角色名]": [台词]` (例如 `"PRTS": 博士, 早上好。`)。此格式在早中期的世界书（如《主线第一至第五章.json》）中极其普遍。
     * **全角冒号分隔型 (Unquoted Name)**：格式为 `[角色名]：[台词]` (例如 `特雷西斯：我们的工程已近尾声。`)。此格式在后期的世界书（如《破碎日冕.json》、《慈悲灯塔.json》）中占主导地位。
