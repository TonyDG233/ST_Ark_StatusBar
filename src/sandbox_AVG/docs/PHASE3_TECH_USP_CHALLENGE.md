# Phase 3: 核心技术奇观攻坚 (The USP Challenge)

## 核心目标
解决《Project Landship》最大的技术壁垒：在双精度大世界上，实现移动巨舰与微缩干员的无缝共存与局部动态寻路，并接入微型 RTS 战斗框架。

## Todo List
- [ ] **构建双坐标系实验田**
  - 创建大世界环境（可以只是一片无限延伸的沙漠平面）。
  - 创建一艘以一定速度向固定方向移动的“陆行舰”父节点（可以用一个几百米长的大方块代替）。
  - 放置大世界摄像机与锁定在舰船上的跟拍摄像机。
- [ ] **死磕动态局部网格 (Chunked/Anchored NavMesh)**
  - 在大方块（陆行舰）上铺设一块局部的 `NavigationRegion3D`。
  - **核心挑战**：确保当方块在世界坐标中移动时，这块子网格也能带着小人一起平滑移动，小人寻路时使用的是方块的**局部坐标系**而非世界坐标系。
  - 阅读 Godot 官方文档关于 `NavigationServer3D` 的进阶篇，研究如何动态更新和烘焙（Bake）子区域的导航地图。
- [ ] **出舱机制与坐标系切换验证**
  - 设计一个出舱口。
  - 实现逻辑：当小人走出舱口触发特定区域（Area3D）时，将其节点从“舰船层级”瞬间 reparent（重新认父）到“大地图层级”。
  - 处理物理继承问题（防止小人出舱瞬间被舰船的碰撞体弹飞，或因为惯性问题发生位移异常）。
- [ ] **接入基于索敌的微型 RTS 战斗**
  - 在局部的废墟网格上，放置敌方单位。
  - 利用简单的 `RayCast3D`（射线检测）实现视野遮挡和射击判定。
  - 连通干员血量与伤害反馈 UI。

## 注意事项与避坑指南
- **做好失败回退的心理准备**：这一步是项目深水区。如果动态跟随网格导致性能崩塌或难以解决的 Bug（耗时超过一至两个月），必须果断退回我们在企划中讨论过的**“视觉欺骗平移法”**（舰船固定在原点，场景倒退移动）。
- **学会查阅底层 API 源码**：到这个阶段，普通的教程已经帮不到你了。你需要习惯阅读 Github 上 Godot 的 Issue 讨论区，以及深入调用 `PhysicsServer3D` 和 `NavigationServer3D` 这种绕过节点系统的底层 API。
