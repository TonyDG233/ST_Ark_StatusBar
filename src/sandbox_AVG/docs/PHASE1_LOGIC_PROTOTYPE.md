# Phase 1: 系统架构与状态机设计 (TS/C# 底座验证)

## 核心目标
在不触碰任何 3D 渲染的前提下，利用你熟悉的纯前端/后端技术栈（TypeScript 或 C#），设计并验证《erArk》式的角色状态机和资源流转逻辑。让游戏的大脑（逻辑层）在终端里跑起来。

## 注意事项与避坑指南
- **防腐层思维**：你的 TS 逻辑代码必须是“纯净”的，绝对不能包含任何与 Godot `Node3D` 或 `Sprite` 相关的字眼。只有这样，无论 Godot 怎么改，你的核心玩法心智模型都不会崩。
- **避免过度设计**：初期不要设计几百个干员属性。先只写“体力”、“心情”、“位置”三个变量，跑通从分配到消耗再到恢复的完整闭环。
