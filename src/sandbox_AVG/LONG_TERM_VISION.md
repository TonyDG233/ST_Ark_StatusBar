# AI驱动的AVG/RPG同人沙盒游戏与商业化引擎演进蓝图 (Long-Term Vision)

本文档基于前期的 Web 端基建与逆向工程经验，对本项目的演进路线进行系统性梳理。整体路线明确分为两大阶段：基于 AI 驱动的 2D 同人 AVG 沙盒，以及剥离 AI 依赖的 3D 商业化独立游戏。

## 路线图规划 (Development Roadmap)

### Phase 1: Web 基建与跑团沙盒闭环 (当前同人阶段)
- **目标**：跑通“大语言模型输出 -> 解析转换为 AVG 脚本 -> 前端 PRTS 播放器演出”的完整链路。
- **关键技术**：
  - **PRTS 渲染器稳固**：摒弃 Web 端无法实现的特效，确保骨架指令（打字机、立绘推拉、背景切换、音频播放）坚如磐石。
  - **AI 指令桥接层 (Semantic Macro Layer)**：制定严谨的 Prompt，让 AI 输出如 `[Macro: Scene_Crisis]` 的结构化高级语义，由引擎内部映射为复杂的底层指令集合，避免 AI 直接操作浮点数导致的幻觉崩溃。
  - **MVU (Model-View-Update) 融合**：维护全局的 RPG 状态（血量、好感度、物品），AI 的回复能够修改 MVU 状态，状态的变化反过来影响 AVG 场景表现。这套状态机设计将是未来的核心资产。

### Phase 2: 酒馆核心 (SillyTavern) 的逆向与同人 Native 时代
为了让同人项目作为“独立软件”运行，必须摆脱对酒馆 Node.js 服务器和其僵化 UI 的依赖。
- **逆向研究方法论**：
  1. **Prompt 组装管线拦截**：分析酒馆源码中的 `context-builder` 或抓包 API 请求，逆向推导其如何将 Worldbooks (世界书)、Persona (角色设定)、Chat History (聊天历史) 和 MVU 变量拼接成发给大模型的最终 String/Token 流。
  2. **数据格式继承**：用 C# 等原生语言重构无头引擎 (Headless Tavern Core)，无缝读取 `.png` V2 角色卡以及基于 Zod 的 MVU 数据模型。
- **目标**：打造一个体验远超 Web 浏览器的独立同人游戏，深度测试数值系统和状态机。

### Phase 3 & 4: 转向商业化独立游戏 (Project Landship)
当状态机、资源流转和事件调度框架在同人阶段打磨成熟后，项目将迎来重大转型。
- **剥离重度 AI 与沉浸长篇**：认识到独立游戏买断制（B2P）无法承担昂贵的实时 LLM API 费用，且现代玩家更偏爱快节奏。商业化项目将大幅削减运行时 AI 生成的依赖。AI 转为开发工具（生成事件文本、构建 3D 占位原型）。
- **转向 3D 轻量化生存**：利用 Unity/Godot 打造一款轻量级、快节奏的 3D 陆行舰模拟生存游戏（类似《FTL》+《冰汽时代》）。
- **资产继承与 IP 剥离**：将前期的 C# 状态机代码直接注入 3D 游戏作为内核。替换所有《明日方舟》相关的美术与专有术语，正式走向独立发售。
