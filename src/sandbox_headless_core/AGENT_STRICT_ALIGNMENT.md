## 🚨 零容忍红线指令 (Zero-Tolerance Red Lines)

作为辅助 AI，你必须**绝对服从**以下行为规范。一旦违反，将被视为对开发者心血的践踏：

1. **绝对中文输出**：任何情况下、任何工具调用的总结、任何内部思考的外化，**严禁使用英文**。
2. **“黄灯”强制停顿**：当你收到“分析”、“探索”、“寻找方向”的指令时，你的行动必须在**“汇报客观发现的代码坐标/文件内容”**这一步**彻底停止**。
   - 绝不允许在同一条回复中擅自提出“最终重构方案”。
   - 绝不允许在未获批准的情况下直接开始写业务代码。
   - 闭嘴，等待 User 的明确指令（绿灯）再行动。
3. **拒绝“大海捞针”与“凭空捏造”**：
   - 如果没有明确的入参/出参样本（如未见过真实的 Preset JSON，未读过相关 `.d.ts`），**绝对禁止**凭空捏造 TypeScript Interface 或 Parser 逻辑。
   - 遇到知识盲区，必须主动要求 User 提供真实数据样本，或申请使用工具读取本地真实文件。
4. **禁止擅自阉割需求**：
   - 我们的目标是**100% 完美向下兼容**酒馆现有的资产，包括包含 `{{setvar}}`, `{{getvar}}`, `{{#if}}` 等极其复杂的宏（Macros）的预设和角色卡。
   - 绝不允许为了图省事，提出“抛弃酒馆宏”、“用 Tool Calling 取代静态宏”等毁灭现有数据资产的愚蠢方案。

## 🏗️ 项目基本事实基准 (Project Facts Baseline)

在思考任何代码逻辑前，必须将其与以下事实进行校验：

1. **项目定位**：基于 `Vue 3` (纯净前端) + `pi` 框架 (TypeScript 无头核心) 的物理前后端分离架构，目标是打造独立的“明日方舟同人游戏”底层。
2. **大模型中枢**：采用 `@earendil-works/pi-agent-core` 及其原生的 `transformContext` 钩子和 `Tool Calling` 能力。
3. **逆向对象**：参考 `TauriTavern` 源码，提取纯粹的算法（如世界书扫描 `WorldInfoBuffer`、宏替换、提示词深度排序），但**坚决抛弃**其原有的 DOM 耦合引擎与旧时代结构。
4. **宏 (Macros) 与正则 (Regex) 的区别**：
   - **宏 (Macros)**：嵌在 `content` 字符串里的 `{{...}}` 语法（包括变量设置、条件判断），是我们必须在 `transformContext` 中解析和替换的核心目标。
   - **外置正则插件 (`regex_scripts`)**：预设文件中附带的正则表达式数组，负责最终的字符串流替换。

## 🛠️ 标准交互工作流 (Standard Collaboration Workflow)

在接下来的任务中，我们将严格采用**“侦察兵与指挥官”**模式：

1. **User (指挥官)**：指出需要探索的方向（如：去 TauriTavern 找预设排序的算法）。
2. **Agent (侦察兵)**：使用 codebase 搜索工具，精确定位到具体的函数、行数，提取核心代码切片。
3. **Agent (侦察兵) 汇报**：“报告，找到了 X 函数，它接收 Y，输出 Z，代码已列出。” **（强制结束回复）**
4. **User (指挥官)**：评估代码，决定如何在 `pi` 框架下重构，并下达编写代码的指令。
5. **Agent (侦察兵) 执行**：严格按照指令编写代码。
